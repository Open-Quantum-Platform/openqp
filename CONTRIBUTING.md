# Contributing to OpenQP

OpenQP welcomes scientific discussion, issue reports, benchmark and validation
data, documentation corrections, and interoperability proposals. Because
current OpenQP releases use a research/commercial licensing model, code is not
accepted under an implied "inbound equals outbound" rule.

## Before submitting code

Please open an issue or contact the maintainers before preparing a code change.
A code contribution can be merged only when one of the following is recorded:

- it was created by a person whose employment, founder, or contractor agreement
  gives Open Quantum Inc. the necessary rights; or
- the contributor and, when applicable, the contributor's employer or
  institution have executed the required written contributor agreement.

The intended external-contributor model allows contributors to retain their
rights in their original work while granting Open Quantum Inc. the durable
copyright and patent permissions needed to maintain, distribute, sublicense,
and license the combined platform under both research and commercial terms.
The exact signed contributor agreement controls. This file and the act of
opening a pull request are **not** a copyright assignment or a substitute for
that agreement.

## Provenance requirements

Every contributor must be able to identify the origin of the submitted work and
their authority to submit it. Do not submit:

- code copied or closely translated from a third-party implementation unless
  the maintainers have approved the license and provenance in writing;
- work owned by an employer, university, sponsor, or collaborator without the
  required permission; or
- generated or assisted code that has not been reviewed by a responsible human
  author for correctness, originality, third-party similarity, and license
  compatibility.

Record relevant papers, specifications, clean-room boundaries, third-party
licenses, and validation data in the pull request. A Developer Certificate of
Origin sign-off may document provenance, but it does not replace the written
rights needed for OpenQP's commercial relicensing model.

## Scientific and engineering expectations

Approved changes should include focused tests, relevant reference data and
provenance, user-facing documentation, and a clear account of numerical
tolerances and changed defaults. Preserve third-party notices and do not weaken
release, licensing, or reproducibility checks.

See [SUSTAINABILITY.md](SUSTAINABILITY.md) for the project's community rationale,
[LICENSING.md](LICENSING.md) for the licensing guide, and `AGENTS.md` for the
repository's engineering rules.
