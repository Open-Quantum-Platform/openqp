# OpenQP v1.3.0

OpenQP v1.3.0 expands correlated-wavefunction, excited-state, dynamics, and
interoperability capabilities. It is also the first tagged release governed by
the OpenQP Research License 1.0 and the separate commercial-licensing model.
The v1.2.1 and earlier release tags retain the GPLv3 terms that accompanied
those copies.

## Highlights

- Added parallel closed- and open-shell CCSD(T), including restricted,
  unrestricted, Cholesky, direct-Cholesky, and frozen-core validation routes
  ([#302](https://github.com/Open-Quantum-Platform/openqp/pull/302)).
- Added production-oriented nonadiabatic-dynamics validation and restart
  records, finite-droplet QM/MM boundaries, native ODP umbrella sampling and
  WHAM, and SOC-NAMD/QM/MM provenance gates
  ([#313](https://github.com/Open-Quantum-Platform/openqp/pull/313),
  [#314](https://github.com/Open-Quantum-Platform/openqp/pull/314),
  [#315](https://github.com/Open-Quantum-Platform/openqp/pull/315),
  [#316](https://github.com/Open-Quantum-Platform/openqp/pull/316)).
- Added physical-root MRSF state analysis and portable MO, vibrational, and
  Dyson-orbital exports
  ([#290](https://github.com/Open-Quantum-Platform/openqp/pull/290),
  [#310](https://github.com/Open-Quantum-Platform/openqp/pull/310)).
- Added the optional OpenQP-XTB backend and a complete, separately loaded GPU
  attachment for SCF, DFT, MRSF, and gradients
  ([#269](https://github.com/Open-Quantum-Platform/openqp/pull/269),
  [#265](https://github.com/Open-Quantum-Platform/openqp/pull/265)).
- Adopted the prospective research/commercial dual-license structure. Earlier
  GPL-tagged releases remain GPL and are not retroactively relicensed
  ([#292](https://github.com/Open-Quantum-Platform/openqp/pull/292)).

## New features and scientific capabilities

### Coupled cluster and perturbation theory

- Implemented perturbative triples for closed- and open-shell CCSD references,
  parallelized the main contractions, and added PySCF-derived reference data,
  input validation, examples, and direct/Cholesky coverage
  ([#302](https://github.com/Open-Quantum-Platform/openqp/pull/302)).
- Added the missing second-order singles contribution to ROHF MP2 and regression
  coverage for the corrected ROMP2 energy
  ([#305](https://github.com/Open-Quantum-Platform/openqp/pull/305)).

### MRSF, symmetry, and analysis

- Added a physical-root state-analysis API with spin, transition, and dominant
  configuration information designed for programmatic downstream use
  ([#290](https://github.com/Open-Quantum-Platform/openqp/pull/290)).
- Enabled symmetry detection and labels by default and made the Davidson guess
  cover every eligible symmetry block, preventing requested roots from being
  omitted merely because an earlier block filled the initial guess
  ([#317](https://github.com/Open-Quantum-Platform/openqp/pull/317)).
- Cleared staged symmetry metadata whenever the state it describes becomes
  invalid, closing a live-state lifetime error in repeated calculations
  ([#329](https://github.com/Open-Quantum-Platform/openqp/pull/329)).
- Corrected UMRSF mixed-exchange channels and dipole moments
  ([#299](https://github.com/Open-Quantum-Platform/openqp/pull/299),
  [#298](https://github.com/Open-Quantum-Platform/openqp/pull/298)).

### Dynamics, state tracking, and crossing searches

- Bound MO and electronic-root identities across in-memory drivers, numerical
  NAC evaluations, restarts, and delayed hops. Numerical NAC orientation and
  scale were corrected, raw finite-state overlaps are retained, and trivial
  crossing following is now opt-in
  ([#160](https://github.com/Open-Quantum-Platform/openqp/pull/160)).
- Added strict NAMD checkpoint, restart, RNG, tracking, phase, coefficient,
  Hamiltonian, NAC/TDC, energy, and sidecar provenance validation. Accepted
  steps can be resumed without silently mixing incompatible trajectories
  ([#313](https://github.com/Open-Quantum-Platform/openqp/pull/313)).
- Added an independent finite-water-droplet boundary for QM/MM and propagated
  the boundary, force-field, and restart identities into dynamics records
  ([#314](https://github.com/Open-Quantum-Platform/openqp/pull/314)).
- Added native ODP umbrella sampling, restartable windows, ensemble validation,
  and WHAM analysis with explicit topology and temperature provenance
  ([#315](https://github.com/Open-Quantum-Platform/openqp/pull/315)).
- Extended the production record and audit model to SOC-NAMD and SOC-NAMD/QM/MM,
  including two-state trace probabilities and delayed-hop coefficient handling
  ([#316](https://github.com/Open-Quantum-Platform/openqp/pull/316)).
- Added multiplier-based MECI and MECP objectives and made SQP the default native
  MECP method, while retaining explicit alternative routes
  ([#311](https://github.com/Open-Quantum-Platform/openqp/pull/311),
  [#312](https://github.com/Open-Quantum-Platform/openqp/pull/312)).

### Tight-binding, XTB, GPU, and interoperability

- Added `method=xtb`, connecting the separately loaded OpenQP-XTB LC-GFN1-xTB
  and MRSF backend through a versioned runtime ABI
  ([#269](https://github.com/Open-Quantum-Platform/openqp/pull/269)).
- Added an optional, default-off `openqp-gpu` attachment that can accelerate
  SCF, DFT, MRSF response, and gradients without making the GPU package a core
  link dependency
  ([#265](https://github.com/Open-Quantum-Platform/openqp/pull/265)).
- Stabilized DFTB ground-state continuity and geometry recovery, added an ABI-4
  cold-TRAH recovery route, and prevented energy-only gradient backfills from
  being treated as analytic gradients
  ([#287](https://github.com/Open-Quantum-Platform/openqp/pull/287),
  [#288](https://github.com/Open-Quantum-Platform/openqp/pull/288)).
- Added conventional top-level `td-dftb`, `sf`, and `mrsf` routes; RKS, ROKS,
  CUKS, and UKS ground references; solution-following warm starts; the DTCAM-TB2
  response operator; and concise `dtcam`/`ob2` model names with compatibility
  aliases
  ([#294](https://github.com/Open-Quantum-Platform/openqp/pull/294),
  [#297](https://github.com/Open-Quantum-Platform/openqp/pull/297)).
- Added portable Molden MO exports, frequency data, structured Hessian output,
  and Dyson-orbital exports for viewers and external workflows
  ([#310](https://github.com/Open-Quantum-Platform/openqp/pull/310)).

## Performance improvements

- Removed a BLAS-thread pin that serialized OpenQP's own OpenMP two-electron
  integral region
  ([#306](https://github.com/Open-Quantum-Platform/openqp/pull/306)).
- Sized BLAS threading to the actual eigenproblem and documented the ownership
  boundary between BLAS and OpenMP parallel regions
  ([#307](https://github.com/Open-Quantum-Platform/openqp/pull/307)).
- Parallelized the dominant CCSD(T) contractions and added memory-aware blocked
  implementations for closed- and open-shell references
  ([#302](https://github.com/Open-Quantum-Platform/openqp/pull/302)).

## Bug fixes and reliability

- Fixed nonconforming Fortran exposed by bounds-checking builds, including
  tagarray dimensions, masked `maxloc`, and DFT grid-storage reallocation
  ([#300](https://github.com/Open-Quantum-Platform/openqp/pull/300)).
- Made Molden export skip angular-momentum shells that the format cannot
  represent instead of aborting the completed calculation
  ([#304](https://github.com/Open-Quantum-Platform/openqp/pull/304)).
- Hardened degenerate native-coordinate recovery and prevented overflow warnings
  from escaping handled optimizer fallback paths
  ([d1267f2](https://github.com/Open-Quantum-Platform/openqp/commit/d1267f2),
  [3fdbba7](https://github.com/Open-Quantum-Platform/openqp/commit/3fdbba7)).
- Expanded automated coverage for crossing objectives, NAMD records, ODP/WHAM,
  state tracking, symmetry staging, CCSD(T), ROHF MP2, DFTB/XTB ABIs, Molden
  output, and memory guards.

## Packaging, licensing, and CI

- OpenQP v1.3.0 is the first tagged source release under the OpenQP Research
  License 1.0 plus separate commercial licensing. The license only covers code
  for which the licensor has authority; third-party components retain their own
  terms. OpenQP v1.2.1 and earlier tagged copies remain GPLv3
  ([#292](https://github.com/Open-Quantum-Platform/openqp/pull/292)).
- Added Pytest execution to continuous integration and automated reviewer routing
  for the maintained code paths
  ([#293](https://github.com/Open-Quantum-Platform/openqp/pull/293),
  [#289](https://github.com/Open-Quantum-Platform/openqp/pull/289)).
- Synchronized Python, CMake, and legacy package metadata at version 1.3.0 and
  added complete first- and third-party license files to source distributions
  and wheel metadata.
- Release publication is deliberately two-stage. Publishing a GitHub Release
  builds and verifies candidate artifacts but does not automatically publish
  them to PyPI or attach binary wheels. Public binary publication requires an
  explicit tag/SHA/artifact-provenance check and approval in the protected
  `pypi` environment.

### Binary distribution status

The DFT-D4 stack is now shipped as three package-local, replaceable shared
libraries together with its complete patched corresponding source and build
recipe. NLopt has been removed from the build and replaced in E-DIIS/A-DIIS by
a deterministic native simplex-QP solver. The release gates inspect the final
wheel or container dependency table and dynamic symbols, exercise the packaged
DFT-D4 stack, and reject hidden alternate copies.

Public source, wheel, and Docker publication nevertheless remains blocked until
the release checklist confirms the company's chain of title and every other
artifact/provenance requirement for the exact tag and commit.

## Compatibility and upgrade notes

- The default MRSF-TDDFTB operator is the tuned DTCAM model. Historical model
  spellings remain accepted as aliases, but new inputs should use `dtcam` or
  `ob2` as documented.
- Symmetry detection and labels are enabled by default. Workflows that require
  deliberately symmetry-free ordering should disable symmetry explicitly.
- Native MECP searches now default to SQP. Select another supported crossing
  objective explicitly when reproducing an older trajectory.
- OpenQP-XTB and OpenQP-GPU remain separately built and dynamically loaded; they
  are not silently bundled into the OpenQP core.
